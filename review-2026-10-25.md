# Codebase review, 2026-10-25

At review time the gate was green: lint, tsc, 391 unit and integration tests and 77 contract tests all passed. Even so, the suite missed several real bugs. Items marked "verified" were confirmed by a throwaway integration test.

## Status

Fixed in three commits on `main`:

- `a61b59a` review fixes (items 1–5, 7, 8, 10, 12–16 and most low-priority items)
- `1397244` design decisions (items 6, 9, 11 and the leave rules)
- `0f96498` performance work

After the fixes, the gate passes with 422 unit and integration tests and 77 contract tests. Every bug fix has a regression test that failed on the old code, except where noted. Open items are listed at the end.

## High

1. **Entry times shift by the browser's zone offset.** Fixed in `a61b59a`. `src/components/entryForm.tsx` called `new TZDate("2026-09-02T10:00:00", tz)`, which reads the string in the browser's zone. The conversion now goes through `localInstantIso` in `src/lib/dayMath.ts`. Entries already saved from browsers outside the org zone are still stored shifted; see the open items.

2. **Operators could see `rateCents` (#5).** Fixed in `a61b59a`. `listIntervalsFn` now strips the key, as the create and update fns already did. The fn layer has no tests.

3. **An approved week could be edited through a long interval.** Fixed in `a61b59a`. `weekKeysTouched` now returns every week a range covers. Intervals are also capped at 7 days, which fails with the new code `INTERVAL_TOO_LONG` (400, on `endedAt`) in both the schemas and the services.

4. **"My weeks" disabled Submit unless the week had a Monday entry.** Fixed in `a61b59a`. `weeksWithEntries` now checks the whole week.

5. **`per_hours_worked` leave accrued almost nothing.** Fixed in `a61b59a`. Worked time is now counted over the whole accrual year, not just its first day.

6. **Archiving an admin left their BetterAuth admin rights intact.** Fixed in `1397244`. `archiveWorker` now sets the person's BetterAuth role back to `user`, bans them and deletes their sessions in the same batch. Correction to the original finding: BetterAuth already stops admins impersonating other admins by default. The real risk was `set-user-password` on an active admin, or impersonating any non-admin.

7. **D1's 100-bound-parameter limit was hit by unbounded `inArray` lists** (verified). Fixed in `a61b59a`. Unbounded id lookups now run in slices through `src/server/inChunks.ts`. The CSV export dropped its every-worker filter, client filters became joins, and interval events load through a join. A scale test seeds 120 workers, 120 jobs and a 120-interval week. Operator scope lists are still unchunked; see the open items.

## Medium

8. **Archiving a client or project didn't stop new time.** Fixed in `a61b59a`. The job lookup at interval create and job change now requires the project and client to be unarchived as well.

9. **A position rate replaced a $0 job rate.** Fixed in `1397244`. A position now overrides only jobs priced above zero, so $0 stays a pro bono line as ticket #18 specifies.

10. **The approvals page never refreshed after approve or reject.** Fixed in `a61b59a`. It now uses the router's real `useRouter()`, and bulk approve lists the weeks that failed and why. The UI has no tests.

11. **Billing and admin users couldn't submit their own weeks.** Fixed in `1397244`. Approvals now has Queue and My weeks tabs for approvers, and submitting refreshes the list. The UI has no tests.

12. **`setPrimaryContact` didn't await its batch.** Fixed in `a61b59a`. It now awaits the write, and returns 404 `CONTACT_NOT_FOUND` for a contact from another client or one that's archived.

13. **Detail pages capped at 200 rows.** Fixed in `a61b59a`. `getClient`, `getProject` and `clientFigures` now query rows directly instead of searching a 200-row list.

14. **Week and hour math assumed 24-hour days, which broke in DST zones** (verified). Fixed in `a61b59a`.
    - A new `weekBoundariesUtcMs` helper replaces `start + 7 days` in approvals.
    - `weeklyTrends` steps back in calendar weeks.
    - `adminKpis` walks the day's real hours.
    - Late-entry flags count in calendar days.
    - Found during the fix: `intervalList.tsx` clipped rows to UTC days. It now uses the queried local day.

15. **Invoice lines could contradict themselves.** Fixed in `a61b59a`. There is now one line per job and rate, so each line's minutes × rate equals its amount.

16. **Interval writes weren't atomic.** Fixed in `a61b59a`. The interval write, its audit event and any submitted-week reset now run as one `db.batch`. Guard-then-write races are still open; see the open items.

## Low and quality

- **Unnecessary server imports and debug span in the approvals route.** Fixed in `a61b59a`.
- **Quadratic and per-row queries.** Fixed in `0f96498`. This covers the intervals CSV, the approvals queue and team view, and the leave queue, report and export.
- **Dead and wrong code.** Partly fixed in `a61b59a`: the `void groupBy` hack is gone. `findSameJobOverlaps` (unused, only compares neighbouring intervals) and the duplicate `dayOfPieceStart` remain.
- **Weak input validation.** Fixed in `a61b59a`. Client and project figures require ISO dates, export and invoice periods reject `to` before `from`, and leave days must be real calendar dates.
- **Leave counted every calendar day, and overdrawn balances reset to 0.** Fixed in `1397244`. Requests count Monday to Friday, and a request with no weekdays fails with `LEAVE_NO_WORKDAYS` (400, on `endDay`). An overdrawn balance now carries into the next year as a negative.
- **Error codes drifted from CLAUDE.md.** Documented in `a61b59a` and `1397244`: every thrown code is now listed. `ROLES_MISSING_OPERATOR` and `ROLES_MUST_INCLUDE_OPERATOR` remain two separate codes.
- **Red-flag details show raw ids.** Open.

## Open

- **Saved times from fix 1.** Intervals entered from browsers outside the org zone before `a61b59a` are stored shifted, and need a one-off data repair.
- **Operator scope lists.** A supervisor with more than about 95 direct supervisees would still exceed D1's 100-parameter limit in the grouped report queries.
- **Guard-then-write races.** An overlap or approval can still land between the checks and the batch. D1 has no interactive transactions, so closing this needs conditional writes.
- **Worker filter in `projectFigures`.** At `src/server/services/projects.ts`, `{ workerIds, ...scope }` lets the operator scope overwrite the worker filter. This looks unintended.
- **`allProjects` breaks CLAUDE.md rule 10.** It's a new exported function in a services file. Moving it to its own file would follow the rule literally.
- **Impersonation audit gap.** App admins can still impersonate non-admins, and those actions are recorded under the impersonated worker.
- **Public holidays count as workdays.** There's no holiday calendar.
- **Leave balances changed for past requests.** The weekday and overdraw rules apply to existing requests, so balances people have already seen will move.
- **Stale CLAUDE.md note.** It still lists a phase4 contract failure that no longer happens.
