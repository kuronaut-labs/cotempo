## Notes

**Domain:** time tracking / workforce management for AI-agentic tech companies.

**Standing decisions (pre-map, from destination grilling):**
- Overlap model: **Duplicate** — overlapped minutes bill fully to each concurrent job (3 jobs x 1hr = 3 billable hours from 1 wall-hour). Honest capture over fair-split.
- Single truth: raw intervals are the source of truth; billing and honest views are derived.
- Workers: humans and AI agents are both first-class workers. Operators supervise multiple agents.
- Time entry: human operator enters hours for both humans and agents (for now). Agent auto-entry is roadmap.
- Roles: operator, admin, billing/approver. No other roles identified.
- Tenancy: single-org for now (not multi-tenant SaaS).
- Platform: web-based. **Stack locked: TanStack Start (React) + Cloudflare D1 + Drizzle ORM + BetterAuth, deployed on Cloudflare Workers.** Full-stack (server functions + server routes for protected API).
- UX bar: easy, simple, modern. Entry UX model undecided.

**Out of scope (roadmap):**
- Agent auto-entry of hours
- Agent framework integrations (LangGraph, CrewAI, etc.)
- Client portal
- Mobile app

**Skills to consult:** frontend-design (for entry UX and admin views), writing-plans (when ready to plan the build).

**Standing preference (added on reopen):** when a plan departs from a locked decision, the departure is either reverted or recorded here as a refinement on the original ticket's gist. The plan never silently overrides the map.

**Known-stale detail:** #3 and research #1 describe Start deploying via Nitro presets. Start now builds with Vite directly and Cloudflare uses `@cloudflare/vite-plugin`; research #15 supersedes that part of #1. The #3 stack choice itself is unchanged.

## Decisions so far

<!-- the index: one line per closed ticket, enough to judge relevance, then zoom the link for the detail the ticket holds -->

- [Research: Astro vs TanStack Start for protected APIs, auth, and data](tickets/01-research-astro-tanstack.md): Both full-stack capable; Astro = content-first + mature middleware, Start = type-safe app experience + stronger auth primitives. Drizzle is 2026 ORM default.
- [Research: Prior art in concurrent/overlap time tracking](tickets/02-research-concurrent-timesheeting-prior-art.md): No product bills overlapped time at full value; duplicate attribution has legal precedent (CA 1996-147) with disclosure+consent+reasonableness. Allen's Interval Algebra models overlaps. Open niche for agent timesheeting.
- [Stack selection: frontend framework and backend architecture](tickets/03-stack-selection.md): TanStack Start (React) + Cloudflare D1 + Drizzle + BetterAuth, deployed on Cloudflare Workers. Full-stack; D1/SQLite (no PG overlap types, compute in app); accept Start v1.0 freshness. **Refined by #15/#20:** Cloudflare Vite plugin + `cloudflare:workers` env, not Nitro.
- [Data model: workers, jobs, clients, intervals, overlaps](tickets/04-data-model.md): Base+extension worker tables (human_workers, agent_workers); Client > Project > Job (3 levels); intervals as single source of truth with implicit overlaps (computed on demand); supervisor_id FK for operator supervision; billability derived from job.billable_rate; soft-delete (no hard deletes). **Refined by #18:** `billable_rate_cents` nullable integer; `intervals.rate_cents` snapshot. **Refined by #19:** `timestamp_ms` mode everywhere, app-supplied; partial indexes on intervals. **Final shape in #24.** Billing view = duplicate attribution sum; honest view = union of intervals per worker.
- [Roles and permissions matrix](tickets/05-roles-permissions.md): Operator baseline for all humans; billing and admin additive (roles array); admin = superuser. supervisor_id is a hard authorization boundary (supervisees-only entry/edit). Operators see time only — no rates/totals. Billing = view-all + money + approval. Admin owns structure (clients/projects/jobs/rates) and user management. **Confirmed by #17** against a plan drift: admin entry rights on non-supervisees stand. **Refined on plan review (2026-09-08):** no self-approval for billing users (`SELF_APPROVAL` 409); admin exempt, audited like any approve.
- [Billing vs honest view derivation rules](tickets/07-billing-honest-view-rules.md): Honest view = trio (wall-clock union, effort sum, overlap premium) always shown together — premium IS the disclosure (CA 1996-147 posture). Billable = full-duplication sum, exact minutes, no rounding. **Refined by #18:** billable ⇔ `interval.rate_cents IS NOT NULL`; money rounds once per displayed grouping. **Refined by #22:** minute alignment enforced at the Zod edge. **Refined by #23:** boundaries via `@date-fns/tz`; week key in org zone. **Refined on plan review (2026-09-08):** wall-clock for any report grouping = per-worker union summed across workers. Same-job overlap blocked at entry as data error; no concurrency cap. Period-crossing intervals split proportionally (org timezone). Four v1 reports: per-client billing, per-worker utilization, per-job totals, reconciliation.
- [Auth and session approach](tickets/08-auth-approach.md): BetterAuth, email+password only (min 12, no 2FA v1), no public signup — email invitations (BetterAuth admin plugin + HTTP mail API), first admin via seed script. Roles DB-authoritative on human_workers (JSON text), loaded per-request into typed context; server functions = security boundary with in-body guard helpers. Sessions in D1 via drizzleAdapter. Agents never authenticate. **Refined by #16:** invitation = reset-password token flow, 7-day single-use; seed admin via direct hash-and-insert.
- [Entry UX model](tickets/06-entry-ux-model.md): Three-model prototype (timers / timeline / retro) evaluated; v1 was "timeline primary + retro form precise-entry path, live timers deferred to v2." **Superseded by #13** for v1 scope.
- [v1 entry UX revision: retro form only](tickets/13-v1-entry-ux-revision.md): v1 entry surface is the retro form only (worker / job / start / end / Add). Timeline drawing AND live timers both deferred to v2. Day view = read-only intervals for self + supervisees + mini-strip + day-math trio. Timeline Gantt visualization moves to reporting views (#11). Prototype at prototypes/entry-ux.html kept as v2 reference (Model C is the v1 build target). **Refined by #24:** v2 live timers need one nullable `ended_at` migration.
- [Agent worker operational attribute schema](tickets/09-agent-worker-attribute-schema.md): v1 `agent_workers` shape unchanged from #4 ({worker_id, model, framework, status}); no operational attributes added. Run tracking → defer to v2 (separate agent_executions table); token/cost → out of scope (observability owns it); client assignment → pure via jobs/intervals; concurrency limits → app-level config only.
- [API endpoint design](tickets/10-api-endpoint-design.md): Server functions (`createServerFn`) are the primary primitive for all UI-driven CRUD, reporting, billing reads; server routes reserved for `/api/health` (the only public endpoint) and any future cross-origin/webhook consumers. Middleware: global in `src/start.ts` (CSRF + BetterAuth session) + per-fn `.middleware([authMw, roleGuard, superviseeOnly])`. Validation: shared Zod schemas in `src/lib/schemas/`, `.validator()` on every server function. Pagination: cursor-based, Zod-validated search params (default 50, max 200). Conventions: server fns in `src/server/fns/`, routes in `src/routes/api/`, middleware in `src/server/middleware/`. **Refined by #20:** env/db/auth accessors in `src/server/`, `src/lib/` runtime-agnostic. **Refined by #21:** handler bodies exported as plain `(ctx, input)` functions. **Refined by #25:** TanStack Form confirmed; `HttpError.field` error contract.
- [Reporting / admin dashboard design](tickets/11-reporting-admin-dashboard-design.md): Three-tab prototype at `.wayfinder/prototypes/reporting-ux.html`. A · Admin = KPI strip (workers/structure/billable today/premium/utilization) + worker roster w/ utilization bars + today's concurrent-effort bars (overlap hatching) + client→project→job tree w/ rates. B · Billing = period selector + per-client reconciliation table (billable/wall-clock/premium trio) + reconciliation bars + org-total trio + CSV/PDF export. C · Operator = self + supervisees lanes w/ day-math chip (no money) + read-only mini-timelines. Signature: reconciliation trio (billable / honest / premium) shown everywhere a number is shown — encodes the #7 disclosure posture directly in the UI. Token system extends entry-ux (#6/#13). Exports: CSV (intervals + derived trio per row), PDF (period invoice per client).
- [Approval workflow: locking, granularity, and flow](tickets/12-approval-workflow.md): Per-worker-per-week approval. Soft lock with re-approval required (admin unlock returns week to operator's queue). Operator submits, billing/admin approves/rejects. Operators blocked from editing approved weeks; admin unlocks + re-approval for corrections. Approver view = reconciliation trio + per-interval list + red flags (large gaps, post-week-end entries, multiple edits, retroactive starts). Schema: new `approvals` table keyed by (worker_id, week_start_date) with `approval_events` audit trail. Refines #5 (operators gain `submit_week`, admin gains `unlock_week`). **Refined by #17:** fifth red flag "entered by non-supervisor". **Refined by #26:** only `approved` locks; `submitted` auto-resets to draft on edit; crossing intervals check both weeks.
- [Research: current TanStack Start on Cloudflare Workers build, bindings, and test setup](tickets/15-research-tanstack-start-cloudflare-2026.md): `@cloudflare/vite-plugin` + `server-entry`, no Nitro; `cloudflare:workers` env import inside server fns (D1 calls only in request context); `createStart(() => ({...}))`, `createMiddleware({type:'function'})`, `.validator()`; tests via `@cloudflare/vitest-plugin` `cloudflareTest()` on Vitest ^4.1 with `applyD1Migrations`; Drizzle D1 async-only, `batch()` not transactions; BetterAuth admin ops need an admin session, invite-only via `disableSignUp` + reset-password or magic link. Supersedes the Nitro parts of #1/#3.
- [Invitation flow: recipient-set password link vs emailed temporary password](tickets/16-invitation-flow.md): #8 stands — link, invitee sets own password. Mechanism = BetterAuth reset-password token: admin-session `createUser` (discarded random password) + `requestPasswordReset` with an invitation-worded template; `disableSignUp: true`; single-use, 7-day token. Bootstrap admin seeded by hashing via BetterAuth's internal context and inserting user/account rows directly. Mail failure: invite persists, admin gets a Resend action, nothing secret ever shown in UI.
- [Billability semantics and billable_rate storage type](tickets/18-billability-and-rate-type.md): `jobs.billable_rate_cents` nullable integer (null = non-billable, 0 = billable at $0); `intervals.rate_cents` snapshot copied at create / job change, so rate edits never re-price approved weeks. Money = round once per displayed grouping of Σ(minutes × rate_cents)/60; invoice authoritative, CSV informational. Hours stay exact minutes.
- [Timestamp representation: one encoding for intervals and audit columns](tickets/19-timestamp-representation.md): #4 stands — integer ms-epoch for every timestamp column, Drizzle `timestamp_ms` mode, app-supplied values (no DB defaults). Intervals get three partial indexes `WHERE deleted_at IS NULL` on (worker_id, started_at), (job_id, started_at), (started_at); approvals get unique (worker_id, week_start). Wire format stays ISO at the Zod edge.
- [Bindings and secrets access pattern in server functions](tickets/20-bindings-access-pattern.md): one `src/server/env.ts` imports `env` from `cloudflare:workers`, Zod-validates lazily on first call, caches per isolate; `getDb()`/`getAuth()` are lazy per-isolate singletons; nothing touches env at module scope. `src/lib/**` is runtime-agnostic (lint-enforced); only `src/server/**` may import `cloudflare:workers`. Types from `wrangler types`. Replaces the plan's three env approaches.
- [Integration test fixture strategy for the Workers test pool](tickets/21-integration-test-fixtures.md): `test.projects` with a Node unit project and a `cloudflareTest()` Workers project; migrations via `TEST_MIGRATIONS` + `applyD1Migrations` in setup; one fixture module (`insertDemo(db)`, deterministic ids) shared by tests and the seed script via `getPlatformProxy`; per-file isolation plus `resetDb()` where tests mutate; `asUser(role)` builds a SessionContext, one real BetterAuth sign-in test. Handler bodies are exported plain functions so tests can call them.
- [Minute alignment: enforce exact-minute intervals at the boundary?](tickets/22-minute-alignment.md): Zod refinement rejects sub-minute start/end (`ms % 60000`), no DB CHECK; `dayMath` takes minute-aligned ms and never rounds; day-split pieces are minute-aligned by construction since IANA offsets are minute-granular.
- [Timezone strategy for org-timezone day boundaries](tickets/23-timezone-strategy.md): `@date-fns/tz` for local midnight; `ORG_TIMEZONE` Workers var via `getEnv()`, no settings table; approval week key derived in the org zone from interval start, stored as `YYYY-MM-DD` text; tests cover UTC, LA, Kolkata, Sydney with spring-forward and fall-back days.
- [Reconcile plan schema with the #4 data model](tickets/24-schema-reconciliation.md): final v1 schema delta. Keep `archived_at` (structure) vs `deleted_at` (intervals); drop `human_workers.email` and `jobs.status`; `ended_at NOT NULL` in v1 (v2 timers add a migration); plan names stand (`kind`, `created_by`, agent-only nullable `name`); folds in #18/#19/#22/#23 columns and indexes; one migration wave including approvals.
- [Client-side form layer: TanStack Form + shared Zod, or hand-rolled state](tickets/25-client-form-validation.md): #10 stands — `@tanstack/react-form` on every form with the shared Zod schemas; `HttpError` gains optional `field`; one `applyServerError` helper maps coded errors to a field or falls back to form-level.
- [Approval lock enforcement: where the approved-week check lives and what it covers](tickets/26-approval-lock-enforcement.md): in-body `assertWeeksEditable` after the supervisee guard on create/edit/delete; checks the interval's week(s) before and after the change, both weeks for Sunday→Monday crossings; only `approved` locks, `submitted` resets to `draft` with an audit event; `WEEK_LOCKED` 409 form-level with `weekStart`.
- [Admin entry/edit rights on non-supervisees' time](tickets/17-admin-entry-rights.md): #5 stands — admin may enter/edit time for anyone; billing stays at operator baseline; the plan's guard is corrected. Approved-week lock (#12) still binds admin. New #12 red flag "entered by non-supervisor" (created_by ∉ {worker, worker.supervisor_id}); no schema change.
- [Reporting daily breakdown view](tickets/14-reporting-daily-breakdown-view.md): Daily sub-tab added to Billing tab in the reporting prototype, alongside Reconciliation. Table shape: rows = days in the selected period, columns = clients, cells = stacked trio (billable / honest / premium). Footer row = period totals (same numbers as Reconciliation, just laid out by day). Coexists with the Reconciliation sub-tab. No schema change; daily cells are a query on intervals by date. No change to #12 (daily is read-only reporting; approval remains per-worker-per-week).
